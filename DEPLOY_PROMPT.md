# Промпт для публикации и развёртывания

Скопируйте этот промпт в рабочий Codex/терминальный агент после предоставления рабочего SSH-доступа:

> Подготовь и опубликуй текущий проект «Войти в IT» в `https://github.com/vhudoverdiev/vhudoverdiev.git`, затем разверни его на `root@135.106.139.229` для домена `vhudoverdiev.ru`.
>
> Перед изменениями на сервере сначала проверь SSH, ОС, активные процессы и службы, Nginx/Apache, какие сайты обслуживают порты 80/443, DNS и сертификаты. Старый сайт нужно вывести из эксплуатации, но сначала сделай резервные копии его конфигурации и базы, зафиксируй сервисы/порты и проверь, что копии читаются. Не удаляй старые данные, пока новый сайт не прошёл проверку по домену. Используй `/opt/vhiti`, отдельную MariaDB-базу `vhiti`, Gunicorn под systemd и Nginx. Используй `deploy/setup_server.sh`, systemd/Nginx конфиги и миграции из репозитория; адаптируй команды к фактической ОС сервера.
>
> Установи зависимости, выполни миграции, создай администратора интерактивно (пароль не коммить и не выводи в публичный лог), подключи HTTPS через Certbot после проверки DNS, проверь главную страницу, вход, админ-раздел, логи systemd и автозапуск после перезагрузки. Настрой автоматический деплой GitHub Actions из `main`; SSH-ключ и секреты должны храниться только в GitHub Actions Secrets и на сервере с правами доступа. Не публикуй секреты.
>
> Если SSH недоступен, остановись до серверных изменений и сообщи точную ошибку. Перед финальным переключением домена проверь, что старый сайт и база имеют резервные копии и что новый сервис отвечает локально и через HTTPS.
